# DFT Lab 工程架构与版本边界

这是一条可复现的教学链路：功能 RTL → 综合网表 → 可测性规则检查 → 扫描替换与串链 → 组合 ATPG → 故障仿真 → 完整 DUT 的扫描回放 → 覆盖率与代价分析。网页解释与源码来自同一工程；报告由实际运行产生。

## 被测系统

`dft_demo_top` 接收32位数据，经过4路滚动签名状态形成结果，把结果写入32×32同步memory，并通过配置接口读取状态。它不是CRC或密码学模块，因此沿用已有的 `packet_mix` 名称，不为了匹配早期蓝图改名为CRC。

接口约定：ready/valid共同为1的采样边沿接受事务；下一正沿计算，再下一正沿提交写入。输出接收端始终可接收。key只在idle修改。memory为read-first，未初始化地址保持X；不能为了波形美观偷偷清零。

v0保留5组教学结构：重汇聚、冗余支路、多时钟/分频/门控/负沿、内部异步复位、memory与shadow逻辑。综合后实际结构为293个FF（289正沿、4负沿）、1个门控锁存器、1个memory黑盒；1,760个通用单元不是NAND2等效门数。

## 各版本承担什么

| 版本 | 新增能力 | 新增复杂度和边界 |
|---|---|---|
| v0 | 功能基线、结构反例、JSON与Verilog网表 | 保留不可控时钟/复位、memory边界问题 |
| v1 | 全部293个显式FF替换为扫描单元，统一测试时钟、复位接管、单链 | 需保持使能、复位值与正负沿语义；memory输出X问题保留为警告 |
| v2 | 4条链、main/aux受控测试时钟、4个跨域Lock-up、memory写门控与旁路 | 链长为74/73/73/73；模式切换、相位和短链填充必须遵守协议 |
| v3教学阶段 | 从v0实际fault_cone提取故障图，ATPG、故障仿真、coverage与v2扫描回放 | 是算法/模式阶段，不另复制一套无差异RTL；22故障局部cut不冒称全芯片coverage |

v1和v2生成网表都保留功能模式；实际功能事务回归、扫描装载/捕获/卸载及反例检查分别验证不同责任。单项PASS不能替代其他验收。

## 目录为什么这样分

| 目录 | 输入 | 产出 | 边界 |
|---|---|---|---|
| rtl/v0 | 功能规格 | 可综合模块与memory行为/黑盒模型 | 不硬编码测试向量 |
| rtl/v1、rtl/v2 | 测试策略 | SDFF、测试控制、Lock-up等模型 | 模型不冒充工艺库签核单元 |
| netlist/v0 | RTL与Yosys脚本 | design.v、design.json | 生成物不可手改后声称可复现 |
| netlist/v1、v2 | 实际JSON与scan变换 | 完整扫描网表的Verilog/JSON | 只修改显式支持的单元和连接 |
| dft_tools | 结构网表和配置/协议 | 解析、DRC、插链、ATPG和故障统计 | 算法不夹带网页布局 |
| scripts | 参数、源文件 | 工具执行与原始日志 | 失败传播非零返回码，内部不硬编码本机路径 |
| tb | 协议与规格 | 编译仿真、断言、VCD | 预期不能从被测错误输出直接抄来 |
| patterns | ATPG结果与扫描映射 | 带位序和观察定义的刺激/预期 | 变更链序后必须重新映射 |
| constraints | 时钟与IO意图 | SDC约束草案 | 约束文件存在不等于已跑STA |
| reports | 实际运行 | 日志、JSON、逐故障CSV | 原始分母、失败与范围不得隐藏 |
| build | 编译与仿真 | vvp、VCD、生成TB等 | 不作为唯一的源码来源 |
| docs | 源码、报告与来源核对 | 工程判断、文件档案与复盘 | 解释不代替执行证据 |

## 共享数据契约

`netlist/v0/design.json` 是结构分析的输入；Yosys bit ID与层次映射定义连线身份，网名只作为可读别名。实例必须逐次展开，黑盒内部不可猜测。

`reports/scan_chains.json` 将原FF路径映射为链号、位置和边沿，是扫描TB与ATPG回放共同使用的契约。每个原FF必须恰好出现一次；原门控latch和memory不作为扫描FF。

ATPG以实际fault_cone的11条唯一逻辑线建立22个SA0/SA1 stem故障。正常/故障双电路模拟、32个输入组合穷举和704组HDL交叉核对提供相互补充的证据。完整DUT回放通过真正的SI和SO验证其中一个q/SA1检测，不直接force寄存器绕过扫描。

## 验收与限制

在2026-11-05这次执行中，v1/v2完整功能基线通过；293个FF的逐位扫描装载、捕获、卸载通过；v2 memory旁路与写保护通过。断SI、删除Lock-up、破坏memory写门控的反例被检查拒绝。完整日志以reports为准。

规则零违例只针对实现的规则集合。没有实际Liberty面积映射、完整物理STA、SDF或寄生数据，因此不宣称达到2,000–5,000 NAND2等效门目标或完成Tapeout签核。实际单元数量、教学时序/坐标模型、未测项目在页面分别标注。

依据与核对入口见 `docs/sources.md`；每个源文件的用途、结构、规模、边界和备选见 `docs/file_cards.json`。
