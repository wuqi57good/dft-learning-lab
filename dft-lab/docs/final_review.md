## 本次实际结果

- v0 为293个FF，含4个负沿FF；v1为一条293位链，v2为74/73/73/73四条链和4个Lock-up。
- v0规则报告278个error、1个warning；v1为0个error、1个memory输出警告；v2为0/0。只覆盖已实现的教学规则。
- 两个扫描版本保留原完整功能事务回归，并通过293FF装载、捕获和卸载检查。v2核对memory写保护与已知旁路捕获。
- ATPG的22个组合cut故障中19个可测、3个不可测；原始fault coverage为19/22=86.36%，不是全芯片覆盖率。
- 22×32=704组HDL好/坏输出与Python独立核对；完整DUT扫描回放q/SA1在SO观察到good=0、bad=1。
- 删除SI、Lock-up、memory写门控或ATPG注故障的指定反例被测试拦截；反例日志不应被误读为正确版失败。
- 没有工艺面积与完整物理STA签核。2,000–5,000 NAND2等效门目标尚待真实库映射验证。

具体数值以本包reports中的实际运行记录为准。修改源码、链序、协议或故障集合后应重跑，不沿用旧百分比。

## 二十四题与参考解析

### 01 · 功能仿真全部通过，为什么还要制造测试？

功能验证检查设计是否符合规格；制造测试面向制造后具体芯片的缺陷。正确设计的硅片仍可能有开短路等缺陷。stuck-at 是这些缺陷的一种逻辑抽象，不能直接把功能测试通过率当作故障覆盖率。证据：functional_tb 与 fault_sim 使用不同的目标和通过条件。

### 02 · Scan 如何降低内部状态控制的难度？它没有解决什么？

把内部 FF 连接为串行可访问状态，给组合 ATPG 提供可控 Q 和可观察捕获状态。它不自动生成检测向量，不保证 memory 内部可测，不修复所有时钟/复位/物理时序问题。用 scan_chains.json 指出一个 word_q 的位置。

### 03 · scan_en 与 test_mode 的职责有什么不同？

test_mode 选择测试会话下的时钟、复位和宏边界策略，通常在安全停钟窗口切换；scan_en 决定 FF 在当前协议阶段选 SI 还是功能 D。Capture 时 scan_en=0 并不意味着 test_mode 必须退出。混淆两者可能使捕获时重新启用不受控复位或宏写入。

### 04 · 为什么带 enable 的 FF 不能把 scan MUX 放在 enable 之内？

若先判断 enable，再选择 SI/D，enable=0 时 FF 在 Shift 不移动，整条链局部冻结。Scan 选择应优先于功能保持条件；功能模式仍保留 enable=0 时的 q。检查生成 SDFF 的 next-state 表达式。

### 05 · 293 个 FF 为什么不包含 32×32 memory 的每一位？

综合视图将 memory 保留为一个黑盒实例，其内部结构未知；不能把行为数组位数当作可替换的标准 FF 数。扫描工具只处理支持的显式 FF 单元。Memory 内部测试需要独立方案，外围地址/数据/控制逻辑则可通过扫描和旁路评估。

### 06 · JSON 中两个相同网名一定相连吗？两个不同网名一定分开吗？

都不一定。同名可能属于不同层次实例，不同网名可能是同一个 bit 的别名。连接身份来自实例上下文与 bit 映射，不能靠字符串相等推断。常量 bit 与整数 ID 也须区分。

### 07 · 为什么 keep 属性仍不足以证明冗余故障存在？

综合阶段、共享表达式或后续映射可能改变实际结构。必须检查最终 JSON 中 r 的驱动、消费者和观察路径。若 r 与另一个可观察节点共享了门，本来不可测的故障可能变为可测；证明对象已经不同。

### 08 · 内部异步复位如何破坏扫描？

扫描状态会经过许多功能上不常见组合，可能使 soft_reset 有效。异步复位无需等待测试时钟就清空 FF，已装载向量因此丢失。测试复位接管要保持极性与值，并让模式切换遵守协议；不是永久删掉功能复位。

### 09 · ICG 的 TE 只要连 1 就万事大吉吗？

TE 使测试脉冲能够穿过门控，但仍需确认单元定义、极性、锁存位置和模式稳定窗口。教学 latch+AND 不是已映射工艺 ICG，任意时刻改变控制可能产生毛刺。还需对实际扫描 FF 时钟端验证，不能只看端口名。

### 10 · 为什么负沿段常排在正沿段前面？是否绝对？

在特定同相扫描波形与宏周期定义下，这种顺序能让跨边沿接收端获取所需旧值，减少同周期过度推进风险。结论取决于脉冲次序、SI/SO窗口和相位，不是所有设计不加条件的铁律。必须画出本项目 N→P 边界的两次活动边沿来回答。

### 11 · Lock-up 的透明相位如何选？

目的是让源活动边沿后的新值在目的保持窗口内暂时不能通过。正沿源的常见方案是源时钟低电平透明，源上升沿关闭并保留旧值，下降沿后放新值。不同源边沿应重新推导；选择相反电平可能在最需要阻挡时恰好透明。

### 12 · 降低 scan clock 频率为什么可能修不了 hold？

同边沿 hold 比较最早数据到达与同次目的采样边沿，基本公式不含下一周期长度。若 skew、Tcq,min 和最短路径不变，仅拉长周期并不增加该保持裕量；setup 因下一边沿更晚可能改善。具体波形改变仍应重新分析。

### 13 · 正 clock skew 对 setup 和 hold 的影响为何相反？

以 Δ=目的−源定义，同频同沿模型里目的更晚为最长数据留更多 setup 时间，却要求旧值保持更久，因此减少 hold slack。回答必须带符号定义，不能只说“正偏斜好/坏”。

### 14 · Memory bypass、写门控与 observation point 分别解决什么？

写门控防止测试期间误写；bypass 提供已知可控输入以绕开宏输出 X；observation point 或扫描响应 FF 让差异被读出。三者功能不同，存在其中一个不代表其他问题已解决。旁路也不覆盖 memory 阵列内部故障。

### 15 · D 和 D̅ 表示什么？与未知 X 的关系是什么？

D=(正常1,故障0)，D̅=(正常0,故障1)；它们是可识别差异。X 表示信息不足，不能当作“与0不同所以检测成功”。搜索中的未赋值 X 可通过完成化选0/1，仿真中的宏未知则需控制或掩码，语义不同。

### 16 · 手算 q/SA1 的一个检测向量，并解释冲突回退。

取 a=1,b=0，c 任意：q=~a&c=0，故障q=1；p=a&b=0，所以 reconv 正常0、故障1。若为 p=0 先尝试 a=0，会与激活时选的 a=1 冲突；撤销该分支再选 b=0。其他合法激活路径也可能产生不同向量。

### 17 · 为什么 r/SA0 不可测，而 r/SA1 可测？

r=d&e，z=d|r。SA0 激活时 d=e=1，d 已使 z=1，差异被屏蔽；d=0 时 r本来0。SA1 取d=0，正常z=0而故障z=1。不可测结论绑定当前观察边界，若直接观察r则结论会变。

### 18 · 为什么本工程不是完整 PODEM？

实际实现以故障传播路径、门 cube 和逆向 justification 进行简化 D 算法搜索，未实现完整工业 D/J-frontier。PODEM 有特定的 PI 决策、目标选择和 backtrace/implication 结构；不是所有回溯程序都可称 PODEM。按实现如实命名比采用响亮术语更重要。

### 19 · ATPG 报告未检测，可以直接标 untestable 吗？

不可以。必须区分完整证明、预算中止、不支持模型和 X 阻断。本小锥可穷举32组合验证不可测；一般大电路“没有找到”不等于“不存在”。未解决故障仍须留在原始分母中。

### 20 · 22 个故障的 coverage 为什么不代表整颗 DUT？

它只枚举 fault_cone 的11条stem线各SA0/SA1，没有枚举其他组合锥、每个branch、扫描新硬件、memory阵列或其他故障模型。全DUT回放证明访问与观测路径可工作，但不会把局部故障集合自动扩展成全芯片集合。

### 21 · 为什么要用穷举 oracle 和 HDL 回放两层检查？

穷举为小锥提供完整输入空间的检测性基准，验证搜索与分类；HDL回放验证实际连接、位序、边沿和状态捕获。二者能发现不同错误，任何一层都不能单独替代另一层。

### 22 · 多链长度平衡后为什么还要考虑物理重排？

逻辑上相邻的FF可能相距很远，长扫描线增加布线拥塞和数据延迟。物理重排在允许的边沿/时钟分组内改变顺序，必须更新映射和测试向量并重验。链长相等不等于线长短，更不等于所有时序满足。

### 23 · 如何报告扫描面积开销，才不混淆单位？

先区分通用单元数量与工艺面积。真实面积比较需同一库、映射和面积范围，报告(A_after−A_before)/A_before；NAND2等效门数还需除以相同库参考NAND2面积。未做映射时只给结构数量，不猜测达标。

### 24 · 对外说“项目已跑通”，最少应给出哪些证据？

固定源版本和工具信息、v0功能基线、实际网表盘点、v0/v1/v2规则范围、扫描映射与Shift/Capture回放、ATPG向量及独立故障仿真、原始分母与未测分类、负例被拦截的结果，以及未完成的物理签核项目。网页只是这些证据的阅读入口。

## 五项实操

从连接解释规则：任选 v0 时钟或复位违例，指出原FF、控制来源、v1修复连接与对应验证。验收：不只复述警告文字。
从一位解释整条链：选择word_q的一位，手写SI发送位置、Capture边沿、目标响应位置与SO比较时刻。验收：与真实mapping/TB一致。
从失败解释Lock-up：复现无Lock-up反例，用两个边沿说明旧值如何被新值抢先覆盖。验收：给出偏斜与透明相位，而非只说“跨域不安全”。
从一个故障解释coverage：任选可测故障与r/SA0，分别给向量和不可测证据，指出固定分母。验收：能区分局部cut与全DUT。
从一次变更解释重验：设想将两条链位置互换，列出必须更新的mapping、patterns与回归。验收：不能只改网表就宣布完成。
