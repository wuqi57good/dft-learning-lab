01 / THE BIG PICTURE

先看见全局，再走第一步

唯一主线：Scan + ATPG

制造缺陷可能让一根线永远为 0，或让两个节点意外短接。功能验证回答“设计是否符合规格”，制造测试回答“这一颗做出来的芯片有没有坏”。Scan 为后者增加内部状态的读写入口。

用你熟悉的语言搭一座桥

触发器 ≈ 有时钟的状态变量。组合逻辑根据旧状态和输入计算新值，触发边沿到来时才提交。并行硬件不是顺序执行的 Python。

Scan ≈ 串行状态快照。可以装载与读出大量内部状态；它是单向移位链，不是可以随机访问或双向遍历的链表。

ATPG ≈ 约束求解。同时满足“激活故障、传播差异、抵达观察点”；找不到解不一定是算法弱，也可能电路逻辑上就不存在解。

一个容易混淆的边界

仿真通过 ≠ 芯片可测

功能 testbench 通常从复位开始。ATPG 则希望任意装载内部状态，激活制造故障；门控时钟可能关闭、内部复位可能突然清零、memory 输出可能带来 X。

内部 N 位状态有 2N 种组合，这是状态空间的大小。它不是“所有非 scan 测试都必须运行 2N 次”的通用复杂度定律。

★ 经验点：先把分母说清楚，再谈覆盖率。

02 / WEEK ONE

第一周 · 让“跑通”有证据

10 h · 四个实验单元
012 小时

认识工具，以及它们各自负责什么 ★

为什么做：编译通过只意味着语法和展开成功，不意味着功能正确。把构建、执行、波形分开，才能知道失败发生在哪一层。

最小背景：RTL 是寄存器传输级描述；综合网表是门/触发器实例及连线。Icarus 在数字事件模型里运行 RTL，Yosys 把 RTL 转换为结构。STA 根据延迟和约束检查时序，不能被零延迟 RTL 仿真替代。

iverilog -V
vvp -V
yosys -V
python --version

操作：Windows 可用 OSS CAD Suite 或 MSYS2 安装对应包；Linux 使用本机包管理器。安装路径依平台不同，先确认 iverilog -h、yosys -p "help synth" 可用。工具尚未安装时不得略过失败继续生成“通过”报告。

验收：看到具体版本，不是“命令未找到”。本次实际验证环境是 Icarus 13.0 与 Yosys 0.70（YoWASP）。浏览器动画不需要安装 EDA 工具。

工业界工具对标卡 ↗

本步对应功能仿真与逻辑综合的前置检查；在 DFTCompiler / Tessent 流程之前准备可读入的设计。开源仿真适合本例数字行为，自研工具尚不承担完整工艺库、SDF、DFT 模型和签核职责。商业版本命令需查本机帮助；此处不提供伪造命令。

022 小时

读懂一拍：建立、保持与非阻塞赋值 ★★

为什么做：scan shift 最常见的问题之一是数据太快，capture 常见问题则是数据太慢。它们需要不同的时序预算。

最小背景：Setup 要求数据在采样边沿前稳定一段时间；Hold 要求边沿后继续稳定一段时间。违反这些模拟电路要求可能造成亚稳态，数字仿真一般不会自然重现。两级同步降低亚稳态传播概率，不保证任意速率事件不丢失。

操作：查看 与 ，追踪 IDLE → EXEC → COMMIT。用 <= 表示所有寄存器以同一旧状态计算，再在本拍结束统一更新。

反模式：在 testbench 的 posedge 同时改输入并读输出，会与 DUT 的事件执行发生 race。本项目在 negedge 驱动，在 posedge 后 1 ns 观察；1 ns 是 TB 观察延迟示例，不是芯片延迟模型。

验收：能够解释为什么握手时保存 word，下一正沿更新 result，再下一正沿写 memory；且能指出 scan_en 切换也必须避开时钟的敏感窗口。

工业界工具对标卡 ↗

DFTCompiler / Tessent 需要测试协议中的有效时钟边沿；TetraMAX II / Tessent ATPG 使用对应 capture/shift 过程。实际 setup/hold 签核依赖 STA、工艺库与布线延迟。本批只解释因果并验证 RTL 拍序，不宣称完成 STA。

034 小时

运行、观察、再解释 v0 ★★

为什么做：没有功能基线，插入 scan 后的错误就无法归因。尤其是 memory 的初始 X，不能为让波形好看而偷偷清零。

输入：rtl/v0/*.sv 和 tb/functional_tb.sv。进入工程根后运行：

python scripts/run.py sim

产出：reports/compile.log、reports/functional.log、build/v0/functional.vcd。日志必须含最后一条 PASS FUNCTIONAL_V0，进程退出码必须是 0。

工业界工具对标卡 ↗

本步是 DFT 插入前的功能回归，与工业流程中 DFTCompiler/Tessent 改造前后的仿真对照相对应。第一周验证功能语义；完整 DUT 的 post-scan pattern replay 与局部 ATPG 覆盖率在第六周完成，SDF 时序仿真仍不在本项目验证范围内。

042 小时

证明网表里真的有那个故障靶点 ★★★

为什么做：综合器会删除逻辑冗余，还可能把两个相同表达式合并。源码上存在一个 r，不代表它在门级里仍是独立节点。

操作：运行综合并阅读结构报告。fault_cone 保留层次，p/q 使用 a/b/c，冗余 r 使用独立 d/e；keep 与 -noabc 只是保护手段，最终仍检查真实 AND→OR 连接。

python scripts/run.py synth

验收：reports/netlist_inventory.json 中 redundant_branch_preserved=true、memory_blackbox_instances=1。这些是本项目定义的字段，不是伪造的 Yosys 商业报告格式。

前置知识：JSON 的 bit ID 是网表连接标识。输入和输出连到同一个 bit ID 表示同一根网，不等于两个同名变量。多实例模块统计要按实例展开，黑盒只统计实例、不猜内部寄存器数。

工业界工具对标卡 ↗

对应 DFTCompiler/Tessent 的设计读入、库链接、测试结构盘点阶段。Python 只做本项目局部拓扑验收；工业 DRC 还要理解库中的 scan、clock、reset、时序和测试模型。真实商业命令与报告字段需在已授权环境的 help/man 和流程日志中确认。

一个足够小，也足够真实的子系统

v0 · 13 个 RTL 文件

它接收 32 位数据，计算四路滚动签名，把摘要写进环形 memory，再通过配置端口读回。这里没有把简单异或包装成 CRC：模块名就是 packet_mix，也不提供密码学安全性。

配置地址与 memory 读写契约 0x00 – 0x14

0x00：32 位 key；0x04：soft_reset bit0；0x08：状态；0x0C：memory 读地址；0x10：memory 读结果；0x14：提交计数。未定义地址读 0。memory 同址读写为 read-first，未初始化地址为 X。soft_reset 仅清内部核心状态，配置块保留，因此可写回 0 解除复位。

01

重汇聚：两条路，重新碰面

p=a&b; q=~a&c; y=p|q。检测 q/SA1 时可先选 a=1 激活；为传播再要求 p=0，若错误选 a=0 就冲突，回退为 b=0。

02

冗余：没有解，也是一种结论

r=d&e; z=d|r。r/SA0 的激活要求 d=e=1，但 d 已经把 OR 输出固定为 1，差异不能观测。r 与 p 必须保持独立，避免综合共享产生额外观察路径。

03

时钟：一个 clock 名字远远不够

sys、aux、/4、门控和负沿触发器共存。当前 latch+AND 模型尚无 TE；不能把 RTL 模型称为已映射、已签核的 ICG。v1 修时钟可控性，v2 再讨论跨域 Lock-up 与边沿顺序。

04

复位：移进去的状态可能突然消失

core_rst_n = rst_n_ext & ~soft_reset。扫描改变内部控制时可能触发清零；后续需要测试复位接管，且测试模式切换必须遵守协议。

05

Memory：挡住 X，还得测到周围

memory 不能直接当普通 DFF 串链；写使能要防扫描误写，bypass 要提供已知数据。只把输出 X 遮掉不能证明 Shadow Logic 可测，观察/控制路径还要覆盖外围锥。

门数边界：目标仍为 2,000–5,000 NAND2 等效门。本批实际综合网表为 __CELL_TOTAL__ 个通用单元、293 个 DFF（含使能类型）、1 个锁存器和 1 个 memory 黑盒；这是本次真实统计。缺少工艺 Liberty 面积映射，不能宣称已达到等效门数目标。后续映射后若越界再调整有效数据通路。

第一周自测参考解析 4 题

1. 为什么不直接用功能输入设置每个寄存器？状态之间受转移关系约束，部分状态很难到达。Scan 提供独立的串行装载路径，但仍受测试时钟、复位和链结构约束。

2. r/SA0 未检测到，是否应该增加随机向量？对于 z=d|(d&e) 的独立 r，r 正常为 1 必须 d=e=1，而 d 已将 z 固定为 1。不存在能观测差异的输入；更多向量不能改变逻辑结论。

3. 两个触发器同步后，能否保证任何事件不丢？不能。它降低亚稳态传播概率；toggle 若连续变化快于目标采样，偶数次翻转可能消失。需限制速率或增加握手协议。

4. 为什么不能把 generic cell_total 写成等效门数？AND、XOR、DFF 面积不同，缺少具体库与基准 NAND2 面积不能换算。正规口径应说明映射库、memory 是否计入、总面积与基准面积。
