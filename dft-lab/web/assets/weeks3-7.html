012 小时

综合是编译，却不是把 RTL 翻译成另一种文本 ★★

为什么做：制造缺陷发生在实际电路。RTL 的 reg 可能变成 DFF、锁存器、组合连接，也可能被删除；功能等价的表达式还会被共享。只按源码名字列故障，会漏掉或重复测试对象。

最小背景：把 RTL 看作行为描述，网表看作经过优化的中间表示。门实例是操作节点，bit ID 是图中的连接身份。Yosys JSON 把端口、单元、参数、连接和网名分别保存；一个 bit 可以有多个名字，同名局部 bit 在不同实例中却不是同一根线。常量 "0" / "1" / "x" / "z" 也不能当成整数 bit ID。

python scripts/run.py synth

阅读路线： → netlist/v0/design.json → 。先找 top 的输入，再沿实例端口进入子模块。不要先搜索“有多少个 reg”。本项目保留 fault_cone 教学冗余；普通面积优化可能合法地把它消除。

重点：层次实例必须逐个展开。例如一个含 16 个 FF 的模块实例化两次，实际是 32 个 FF；把模块定义只数一次会漏计。Memory 在综合视图是黑盒：保留接口和实例，不凭空补出 1,024 个可扫描 FF。

错误写法、备选与代价

错误：用网名作字典主键，并把同名节点合并；层次中两个 count 会短接。当前做法：用实例路径区分节点身份，端口连接建立父子 bit 映射，保留原网名用于讲解。备选：先调用工具 flatten 再读 JSON，代码更短，但课程会失去“层次怎么对应”的一部分可见过程。无论哪条路，未知单元、未解析端口和多驱动都应显式报错，不能按直通线猜测。

★经验点：保护教学冗余会牺牲优化自由度；生产网表通常追求功能等价下的面积/时序。因而本工程的故障分母绑定这份实际网表，不能拿优化前后的百分比直接比较。

怎么验收：在报告中复核 293 个 FF、1 个原门控锁存器与 1 个 memory 黑盒；这是当前 v0 的实测结构统计。抽查 u_neg 的 4 个 FF 为负沿，u_mix 的使能条件仍存在。依据：Yosys write_json 格式说明

023 小时

DRC 是对测试协议做结构检查 ★★★

为什么做：shift 时若某个时钟被关闭、某个异步复位被内部状态拉低，扫描链再正确也装不进目标状态。把问题留给 ATPG，会看到大量不可控、X 或链追踪失败，却难以定位根因。

最小背景：DRC 类似带领域语义的静态检查：不仅看语法合法，还看“在指定测试模式下，这个 FF 能否收到边沿、保持复位无效、从 SI 到 SO 是否有连续路径”。它不是自动证明所有物理时序，也不是仿真覆盖率。

v0 的结构证据测试中的后果修复方向与复核

怎么验收：运行扫描流程后阅读 reports/drc/v0.json、v1.json、v2.json。v0 应保留作为反例，v1/v2 的通过只针对脚本明确实现的规则。检查规则必须读取网表连接；仅看到一个叫 test_clk 的名字不能算修复。

进一步核对：驱动索引保留同一 bit 的所有驱动，单元输出互相争用或与顶层输入争用都应报错。扫描替换后还要直接对照原 v0 的每个 FF，核对 Q、D、enable、复位值、触发沿及功能时钟/复位支路；不能只信插链器自己生成的映射。tests/test_drc.py 用 13 项回归验证这些规则，其中包含故意改错的反例。

反模式：把 DRC 的零违例当成 Tapeout 许可

“检查项为零”只说明在本规则集合和输入模型下未发现违例。真实库中的 clock-gating checks、recovery/removal、测试 IO 时序、未知宏行为、功耗限制、物理扫描线长度并未因此获得证明。新增加一种单元时，应先定义检查语义，再扩展解析器与反例；不能让默认分支返回通过。

013 小时

在 D 前加 MUX，也要保留原来的那颗 FF ★★★

为什么做：功能输入很难迅速把数百个内部状态装成一个指定组合。Scan 把状态装载问题转成有协议的串行传输：测试时从 SI 装入，捕获时运行组合逻辑，随后从 SO 读出。它像序列化快照，但链通常是单向移位，不能类比成支持任意访问的双向链表。

最小背景：next_q = scan_en ? si : functional_next。原 FF 若有使能，functional_next = enable ? d : q；Scan 选择必须在功能使能之外，否则 enable=0 的 FF 会在 Shift 停住。异步复位的有效极性、复位值和 posedge/negedge 都是契约的一部分。

原结构必须保留的行为最常见的替换错误
DFF + enable功能态 enable=0 保持；扫描态每个规定边沿移位写成 enable 外层条件，导致 SI 被挡住
低有效异步复位复位有效时异步到指定值；测试态由测试复位控制把低有效当高有效，或把复位值 1 改成 0
负沿 FF功能与测试中都识别其负沿采样语义所有替换统一 posedge，功能行为改变
门控锁存器 / memory保持专用模型与测试控制把它们按普通 DFF 直接串链

代码路线： 读取扁平化连接、识别 FF、建立新单元、改接 SI 并写出两种网表视图。源码浏览器中的新单元模型说明每个端口如何影响真实状态；reports/scan_chains.json 保存原路径与链位置。

为什么不简单替换字符串 DFF → SDFF？

名称相似不保证引脚语义相同。带使能、不同复位值、不同边沿的 FF 必须分别处理；网名也可能被工具转义。正确做法操作结构化连接，并在未知类型出现时失败。另一方案是在 RTL 中手工为每个模块加 scan 端口，便于展示，但改动分散、难保证全部寄存器覆盖；本课程用网表变换集中记录这项决定。

验收：扫描映射中的原 FF 集合与 v0 FF 集合一一相等；不重复、不遗漏，黑盒和原门控 latch 不在扫描 FF 集合中。test_mode=0 时，用原有事务语义验证结果、时钟域和复位行为，而不是只测试“可以编译”。

022 小时

数据通了，还得让时钟和复位听测试协议的话 ★★★

为什么做：scan_en 只选择数据入口，它不会替关闭的时钟造脉冲，也不会阻止异步复位。v1 在测试模式下统一接管时钟与复位，使 Shift 能受外部协议控制；功能模式继续使用原时钟与复位连接。

最小背景：test_mode 是“整段测试会话的配置”，scan_en 是“当前 Shift 或 Capture 的选择”。前者不应每拍跳变。时钟 MUX 的普通组合表达式在任意时刻切换会制造边沿，因此模式切换必须在约定的停钟窗口内进行。

  1. 停止相关功能与测试时钟，并停在测试协议约定的安全电平。
  2. 设置 test_mode、测试复位、TE、旁路及 scan_en；留出稳定窗口。
  3. 先按协议初始化，再解除测试复位；开始完整测试脉冲。
  4. Shift 结束后在非采样窗口切 scan_en，等待组合逻辑稳定，再执行 Capture。
  5. 停钟后退出模式；恢复功能前重新建立有效状态，不能把任意扫描快照当正常业务状态。
错误与备选：为什么“把 reset 永久绑 1”不合适？

低有效复位绑 1 能避免测试态清零，但破坏了功能复位，并失去可控初始化手段。正确接管需要明确功能路径和测试路径。测试模式使用外部 test reset；功能模式保持 rst_n_ext & ~soft_reset。若采用同步复位改造，会改变电路契约，应当是规格决策而不是插链脚本顺手修改。

★经验点：简单时钟 MUX 是本实验的受约束行为模型，不能因仿真中没有毛刺就声称物理安全。工业方案需按库时钟单元、模式控制稳定条件及 STA/CDC/RDC 流程确定实现。

验收：在 Shift 期间改变会影响原内部复位的扫描状态，链状态仍按测试复位契约保持；TE 关闭与打开的结果可区分。DRC 对每个 FF 的实际时钟/复位端进行检查，不能只检查顶层端口“已存在”。

033 小时

链顺序不是表格装饰，它决定了位序和边沿 ★★★

为什么做：一个错误的链位置会让正确 ATPG 向量装到错误寄存器；一个错误的采样窗口会让 SO 整串错位。最容易误判的症状是“几乎对了，只差一拍”。

最小背景：SI → Q0 → Q1 → … → QL−1 → SO。若只考虑同边沿 FF，先送入的 bit 走到链尾；要装目标 Q[0…L−1]，串行输入常按目标的反序发送。混边沿时不能照搬这个口令：必须按 TB 的宏周期定义与末端采样时刻计算映射。

当前安排：v1 使用统一测试时钟，负沿段在前、正沿段在后。此选择与规定的下降沿/上升沿脉冲次序配合，让边界接收端采到预期旧值。它不是脱离波形成立的“所有设计都必须这样排”的定律。需要同时检查 clock waveform、SI 驱动时刻、SO 采样时刻和边沿之间的数据保持。

python scripts/run_scan.py

操作与产出：先看 netlist/v1/design.v 的 SI/Q 连接，再对照 reports/scan_chains.json 和 reports/scan/validation.json。使用不对称图案与 walking bit 验证位序；全 0 和全 1 无法暴露简单错位。停止 Shift 后切换 Capture，再卸出响应，不能只跑 shift loopback 就声称捕获链路已验收。

反例：在活动边沿同时驱动 SI 和读取 SO

TB 与 DUT 的 always 块可能在同一仿真时隙竞争，结果依赖调度次序。当前协议在非活动窗口驱动，明确读取的是更新前还是更新后的值，并等非阻塞赋值完成后检查。备选的 clocking block 能统一定义采样偏移，但这里使用简洁、显式的边沿等待便于初学者追踪。

验收强度：完整 mapping 集合检查负责“有没有漏 FF”，不对称 shift 负责“连接顺序对不对”，Capture 对照负责“功能 D 是否接回来了”，功能回归负责“正常模式有没有被改坏”。四项不能互相替代。

012 小时

链数先由约束决定，再由算法平衡 ★★

为什么做：单条 293 位链至少需要覆盖整条长度的移位操作，长测试集会积累大量机台时间。多条链并行传送可以减少最长链长度，但必须支付扫描 IO、分配网络和时钟控制的代价。

最小背景：这是带约束的负载均衡。仅按 FF 数平均分不够：时钟域、边沿、锁存边界、宏阻挡和空间距离限制哪些元素可以相邻。同步并行 Shift 的周期数由最长链决定，短链需要按协议填充；扫描 FF 数与 Lock-up 锁存器数应分别报告。

当前选择：v2 使用 4 条扫描链，在 main / aux 两条受控测试时钟下运行，并保留边沿分段。4 是本教学实验的选择，不是工业“标准链数”。审读 的分配顺序和约束，再看 scan_chains.json 的实际结果。

★经验点：更多链是否总能缩短测试？

设最大链长为 L、P 个 pattern、每次 Capture 需要 C 个周期。独立装载/卸载的朴素序列约需 P(2L+C) 个周期；若协议允许上一响应卸载与下一刺激装载重叠，则约为 (P+1)L+PC。它们都是协议模型，不能把二者混算。链数增加可减 L，但增加管脚/路由，还可能受测试频率、功耗、ATE 通道和最长链不平衡限制。

错误：按列表轮转分链后便宣布安全。当前做法：先保留边沿/时钟语义，再在允许的分组内平衡，插入所需边界结构。若物理距离很大，宁可略不平衡，也可能比大量跨区长线更合理；这里没有布局数据库，不宣称物理最优。

验收：汇总四条链的 FF 数仍等于原扫描 FF 集合；每条链首尾和长度可回溯到原路径。用不同的每链图案测试，避免两条链接反却因输入相同而蒙混通过。

对应 Tessent Scan / DFTCompiler 的链规划、平衡与物理顺序约束。当前按可见逻辑属性划分，不做 placement、拥塞与真实线长优化。工业扫描重排需要更新最终链序和 ATPG/测试机映射，不能仅移动布线图而保留旧 pattern 位序。

023 小时

Lock-up 保护的是采样窗口，不是“跨域”三个字 ★★★

为什么做：两个正沿 FF 相连时，源 FF 的新 Q 可能很快到达 SI，而目的时钟稍晚。目的端本该接收旧 bit，却可能在自己的边沿前已经看见新 bit，导致同一移位周期多走一级。

最小背景：低电平透明的锁存器在源时钟高相位关闭，保持源上升沿之前的值；到下降沿后才允许新值进入。它人为扩大“旧值仍可用”的时间窗口。若源为另一种边沿，透明相位和边界安排必须重新推导，不能机械复制一个低透明 latch。

手算例子：设源上升沿 t=0，最小 Tcq=0.2 ns，最短数据路径=0.1 ns，目的上升沿晚到 0.8 ns、hold=0.1 ns。无锁存器的新值在 0.3 ns 到达，hold slack=0.3−0.8−0.1=−0.6 ns。若源下降沿在 5 ns，锁存路径的新值在 5.1 ns 才到达，则该次保持比较为 5.1−0.8−0.1=4.2 ns。以上均为示例值，仍须检查下一次接收的 setup。

有 Lock-up 就能接任意异步时钟吗？

不能。扫描时两个时钟必须有明确脉冲次序和稳定关系；任意漂移相位可能落进锁存器透明窗口，或者造成 setup 失败。v2 使用受控 main / aux 测试时钟，跨正沿域边界加入由源时钟控制的低透明 Lock-up。原功能 sys 与 aux 异步不意味着测试时也无协议地自由运行。

反模式：把锁存器写成 always @(posedge clk)，它就变成 FF；或把透明条件写反，刚好在新数据到达时放行。正确判断要画出源活动边沿、锁存关闭/开放窗口和目的采样边沿，再用带偏斜的 TB 检查。本课程的故意错误实验展示数字串位，不把负 hold slack 必然等同于固定的“错一拍”——真实电路也可能亚稳或出现不确定错误。

验收：检查锁存器输入来自哪一个链 FF、控制的是哪一个源时钟；对照有/无 Lock-up 波形。正确结构应在给定测试偏斜下保持预期序列，反例应被断言捕获。Icarus 的延迟模型用来解释因果，不能替代提取寄生后的工艺 STA。

033 小时

Memory 不入链，外围逻辑也不能被遗忘 ★★★

为什么做：Shift 中的随机状态可能把 commit 拉高，误写 memory；未初始化的同步读数据又可能把 X 送进 shadow_parity。既要防止破坏，也要给组合锥可控输入和可观测出口。

最小背景：可控性是“能否把节点设成需要的值”，可观测性是“差异能否到达被检查的位置”。旁路 MUX 像测试用依赖注入：测试态用受控数据替代宏输出，功能态仍读真实 memory。它不测试 memory 内部存储阵列，也不自动保证所有外围故障可观测。

结构本工程的选择必须验证的另一面
写门控test_mode 有效时屏蔽 memory 写使能测试前后已知地址内容不变；功能模式仍可正常写
输出旁路v2 用 test_bypass_data 替代测试态 memory 输出旁路数据能变化，不能只绑死为 0
Shadow 观察外围状态 FF 进入扫描映射；捕获后卸出改变旁路输入时，实际目标响应也应变化
黑盒内部作为非扫描 memory 边界保留不能把外围通过计入 memory 内部 coverage
错误：把所有 X 都替换为 0，覆盖率就上去了

X 可能表示未初始化宏、未知控制或模型缺失。把 X 强行当 0 会把没有证明的差异变成“检测成功”。正确做法优先消除不受控来源；无法消除时，对受污染响应使用明确的比较掩码，并报告因此未检测的故障。ATPG 中的 don't-care X 与四态仿真中的未知 X 意义不同：前者可在完成化时选 0/1，后者不能随意当已知值。

备选：只在输出 mask X 省下旁路 MUX，但会丢失观察能力；增加内部 observation point 可帮助周边锥，却增加面积和新的故障对象。固定故障集合比较前后收益时应明确排除新增结构故障，否则分母变化容易误导。

★经验点：不是每个外围节点都值得加观察点。优先检查未测故障集中在哪条路径、是否受同一 X 来源影响，再评估 observation/control point 的收益、时序与路由代价。本项目提供可解释的小规模证据，不给未经本项目验证的工业覆盖率承诺。

验收：比较 test_mode=0 的 memory 事务、test_mode=1 的写保护，以及旁路输入变化后的 Shadow 捕获/卸出。地址、数据、写控制三类外围路径要分开讨论；单独验证 parity 不能证明写地址译码全部覆盖。

012 小时

先说清楚在测什么，覆盖率才有意义 ★★

为什么做：stuck-at 是针对制造缺陷的抽象模型：假设某条逻辑线永久为 0 或 1。它不是对所有物理缺陷的完整描述，也不等同 RTL 功能测试。一次逻辑测试通常假设单一故障；不能把同时强制多个节点的结果计为某个单故障检测。

最小背景：正常电路输出 G(x)，注入故障 f 后输出 F(x,f)。检测条件是至少一个允许观察且已知的输出满足 G≠F。记 D=(1,0)、D̅=(0,1)，顺序为正常值/故障值；0、1 表示两台电路一致。X 在搜索中表示尚未赋值，完成后的 0/1 向量仍须重新仿真验证。

本项目的精确范围：从 netlist/v0/design.json 的 fault_cone 提取 5 个输入与 6 个门输出，共 11 个逻辑线位置，每个位置各建 SA0/SA1，得到 22 个未折叠 stem 故障。同一个 stem 的故障影响其全部扇出；未单独枚举每条 fanout branch 的故障。这个范围是实际 DUT 的一个组合锥，不是整个 293 FF 子系统的覆盖率。

控制点、观察点与扫描切片的关系

组合切片把已扫描 FF 的 Q 视为可控输入，把被扫描 FF 的 D 或允许检查的主输出视为观察边界。这里的 a…e 对应 word_q[0:4]。组合函数的可检测性仍依赖测试协议能否真正装入该状态，并在正确边沿把输出捕获到可移出的 FF 中；因此需要后面的完整 DUT 回放。

反模式：只用 PI/PO 名字硬编码一张期望表，再称为“网表 ATPG”。当前工具读取门类型和真实 bit 连接建立图；数学公式仅用于独立解释。新增单元必须有可验证的仿真与反推语义，不能默认为 AND 或 wire。

023 小时

简化 D 算法：先激活，再传播，冲突时有依据地回退 ★★★

为什么做：随机输入能碰到一部分检测条件，但稀有激活条件和重汇聚约束需要定向搜索。ATPG 像约束求解：每个局部选择都要与已做出的选择相容，走不通时撤销分支，而不是改写已经被另一条路径要求的值。

最小背景：一个门的 cube 是能使输出满足目标值的一组部分输入条件。例如 AND=0 可由 A=0 或 B=0 达成；AND=1 要求两者都为 1。将输出目标逆向分解到输入叫 justification；沿故障到输出的路径把侧输入设成非控制值叫 sensitization。

当前算法： 枚举故障到观察点的路径，为旁支建立传播条件，再以门 cube 逆向求解到输入。每次决策保存赋值快照，冲突时撤销并尝试其他 cube。候选向量必须交给独立故障仿真确认。它是适合此有限门集的简化 D 算法，不实现完整工业 D/J-frontier，也不把它冒称为 PODEM。

q/SA1 的一条可解释搜索新增约束为什么
激活 q 的故障正常 q=0，故障 q=1，即 D̅q=1 时 SA1 不产生差异
选择使 q=~a&c 为 0 的 cube先试 ~a=0，因此 a=1这是候选，不是唯一选择
沿 q→reconv 传播p=a&b 必须为 0OR 的另一输入若为 1，会屏蔽差异
先试 p=0 的第一个 cube要求 a=0，与 a=1 冲突共享 a 的重汇聚约束显现
撤销失败分支并试另一 cubeb=0；保留 a=1满足传播且不破坏激活

备选方案：PODEM 与穷举各自适合什么？

PODEM 将决策限定在主输入，通过目标选择、backtrace 与 implication 搜索；经典 D 算法可在内部线建立目标约束。二者不是“把 DFS 函数换个名字”。本锥只有 5 个输入，穷举 32 个组合完全可行，因此用穷举作独立正确性 oracle；主搜索仍展示传播与 justification 的工程含义。直接穷举若扩展到数百扫描输入就会遇到指数规模，不能把小例子的秒级运行推广到全芯片。

错误：回溯只撤销最后一个 PI，忘了它引发的中间赋值；后续分支会继承污染。当前做法用明确的分支快照，宁可小规模拷贝，也不先引入复杂增量状态管理。待性能数据证明瓶颈再改 trail stack。

验收：reports/atpg/summary.json 中应有真正由运行产生的决策、冲突与回退记录。不同搜索顺序可能找到不同合法向量或更少回溯；不能为了符合插图而手填日志。原始算法背景：Roth，1966；对照阅读：Goel 的 PODEM 原始论文。

032 小时

没找到向量，先问是没搜完还是没有解 ★★★

为什么做：搜索时间耗尽与逻辑不可测需要不同处理。前者可能需要更好的算法或更大预算；后者加一百万个随机向量也无效。错误分类会使覆盖率报告看似提升，却把尚未证明的问题从分母中删掉。

实际证明：r=d&e; redundant=d|r。r/SA0 激活要求 d=e=1，此时 OR 的直通 d 已为 1，故障被屏蔽；d=0 时 r 本来为 0。两种 d 已穷尽，因此 r/SA0 在现有观察边界下不可测。r/SA1 在 d=0 时可以检测。若新增直接观察 r 的能力，前者可能变得可测，这不矛盾：测试结构和观察边界改变了。

实操：故意把位序反过来，应由哪层测试报警？

现有流程自动运行三种反例：取消故障注入、翻转 a 的装载位、改用错误观察链。它们必须分别被响应或装载断言拦截，正确与错误波形各自保存。可在临时副本继续交换输入位置观察失败，不能通过改期望值让错误映射“重新通过”。恢复后再验证正确版。

百分比之后，保留完整的故障集合 ★★★

为什么做：把未测故障删掉，或把结构变化后的两个分母混在一起，可以轻易做出漂亮曲线，却无法指导测试质量提升。报告应允许读者从任一百分比回到具体 fault ID 与检测它的 pattern。

本项目口径：原始 fault coverage = 已检测故障数 / 固定全部故障数。这里是组合锥的 22 个 stem 故障。若另报“已证明可测集合中的覆盖率”，分母为全部故障减去在相同约束与观察边界下已证明不可测的故障；必须另起名称并同时给出原始分母，不能用它替换原始 coverage。

操作： 用故障 ID 集合累计 union，重复检测只算一次；固定随机种子产生可重复前缀，然后用实际 ATPG 向量补齐可检测故障。观察点对照在 Python 模型中直接增加 r 的可观察性，保持同一目标故障集合；这不是 v2 中新增的实体硬件，也没有为新硬件增加故障对象。

曲线为什么会变平？如何决定下一步？

先区分四类：①激活条件难满足，考虑确定性输入搜索；②差异被逻辑屏蔽，检查传播与观察边界；③Memory X 污染，修旁路/控制或明确 mask；④冗余不可测，提供证明。ATPG 超时属于未解决，不能先归到第四类。重跑随机种子能帮助研究敏感性，但不能把最好看的种子当普遍结论。

★经验点：新 observation point 的收益应按新检测故障、增加的模式/状态、面积和关键路径影响共同评价。固定分母的小锥实验用于解释机制；真正工程优化还需重新建模插入结构及其故障。

验收：累计检测数不下降、不超过故障全集；最后每个未覆盖 fault 都有状态和证据；在相同 pattern 次序下可复现同一曲线。小锥百分比旁始终写明范围，不写成“芯片测试覆盖率”。

023 小时

Shift 常看最短路径，Capture 还要看最长路径 ★★★

为什么做：扫描移位在相邻 FF 之间形成很短的数据路径，容易受正时钟偏斜影响 hold；功能捕获的数据又必须穿过原组合逻辑和新增 MUX，影响 setup。把 Shift 降频可能缓解 setup，却不自动修复同边沿的 hold。

最小背景：定义 Δ=tcapture_clk−tlaunch_clk，正 Δ 表示目的时钟更晚。以下是同频同沿、单周期、忽略 OCV/uncertainty 的教学公式。Hold 比较同一个周期的新数据最早到达；Setup 比较下一采样边沿之前的数据最晚到达。不同边沿、Lock-up、generated clock 与例外约束需要按实际波形改写。

Hold slack = Tcq,min + Tdata,min − Δ − Thold

Setup slack = Tperiod + Δ − Tsetup − Tcq,max − Tdata,max

示例：T=10 ns，Δ=0.8 ns，Tcq,max=0.5 ns，Tdata,max=7 ns，Tsetup=0.3 ns，则 setup slack=3.0 ns。相同正偏斜在该模型中有利于 setup，却不利于 hold。真实分析还要加入时钟/数据路径的早晚角、uncertainty、库条件和寄生参数；不能把这一条路径的公式代入整颗芯片即宣布收敛。

为什么 1,760 个通用单元不等于 1,760 个 NAND2？

AND、XOR、MUX、DFF 的实现面积和逻辑能力不同。Yosys 的 generic cell count 可以比较连接结构，但不提供工艺面积换算。若未来使用同一个 Liberty 映射 v0/v1/v2，应保存映射策略与优化选项；否则结构优化变化也会混进所谓“DFT 开销”。目标 2,000–5,000 NAND2 等效门尚需工艺映射验证，不能用未经验证的经验权重宣布达标。

重排反模式：只按两点距离贪心连接，跨越不允许的边沿/时钟边界，然后继续使用旧 ATPG bit order。正确流程在允许分组内优化，重新导出链映射，再跑 shift 与 pattern 回放。示例曼哈顿距离只是教学量，不是 routed wirelength。

验收：报告逐项标注“实际网表统计 / 示例计算 / 尚未测量”。能手算一个负 hold 和正 setup 的例子；能说明 SDC 中 false path 或 clock group 是分析意图，不应为消除报错随意设置。OpenSTA 官方仓库列出 Verilog、Liberty、SDC、SDF、SPEF 等输入；本项目没有借此宣称已经完成 OpenSTA 签核。

ENGINEER READINESS

入职能力检查 · 先作答，再展开解析

24 题 + 5 项实操

每题先用自己的语言写出答案，再指出一个本工程中的对象或证据。能背名词但找不到实际连接，只能算“认识”；能复现反例并解释修复，才算掌握。

01 · 功能仿真全部通过，为什么还要制造测试？

功能验证检查设计是否符合规格；制造测试面向制造后具体芯片的缺陷。正确设计的硅片仍可能有开短路等缺陷。stuck-at 是这些缺陷的一种逻辑抽象，不能直接把功能测试通过率当作故障覆盖率。证据：functional_tb 与 fault_sim 使用不同的目标和通过条件。

02 · Scan 如何降低内部状态控制的难度？它没有解决什么？

把内部 FF 连接为串行可访问状态，给组合 ATPG 提供可控 Q 和可观察捕获状态。它不自动生成检测向量，不保证 memory 内部可测，不修复所有时钟/复位/物理时序问题。用 scan_chains.json 指出一个 word_q 的位置。

03 · scan_en 与 test_mode 的职责有什么不同？

test_mode 选择测试会话下的时钟、复位和宏边界策略，通常在安全停钟窗口切换；scan_en 决定 FF 在当前协议阶段选 SI 还是功能 D。Capture 时 scan_en=0 并不意味着 test_mode 必须退出。混淆两者可能使捕获时重新启用不受控复位或宏写入。

04 · 为什么带 enable 的 FF 不能把 scan MUX 放在 enable 之内？

若先判断 enable，再选择 SI/D，enable=0 时 FF 在 Shift 不移动，整条链局部冻结。Scan 选择应优先于功能保持条件；功能模式仍保留 enable=0 时的 q。检查生成 SDFF 的 next-state 表达式。

05 · 293 个 FF 为什么不包含 32×32 memory 的每一位？

综合视图将 memory 保留为一个黑盒实例，其内部结构未知；不能把行为数组位数当作可替换的标准 FF 数。扫描工具只处理支持的显式 FF 单元。Memory 内部测试需要独立方案，外围地址/数据/控制逻辑则可通过扫描和旁路评估。

06 · JSON 中两个相同网名一定相连吗？两个不同网名一定分开吗？

都不一定。同名可能属于不同层次实例，不同网名可能是同一个 bit 的别名。连接身份来自实例上下文与 bit 映射，不能靠字符串相等推断。常量 bit 与整数 ID 也须区分。

07 · 为什么 keep 属性仍不足以证明冗余故障存在？

综合阶段、共享表达式或后续映射可能改变实际结构。必须检查最终 JSON 中 r 的驱动、消费者和观察路径。若 r 与另一个可观察节点共享了门，本来不可测的故障可能变为可测；证明对象已经不同。

08 · 内部异步复位如何破坏扫描？

扫描状态会经过许多功能上不常见组合，可能使 soft_reset 有效。异步复位无需等待测试时钟就清空 FF，已装载向量因此丢失。测试复位接管要保持极性与值，并让模式切换遵守协议；不是永久删掉功能复位。

09 · ICG 的 TE 只要连 1 就万事大吉吗？

TE 使测试脉冲能够穿过门控，但仍需确认单元定义、极性、锁存位置和模式稳定窗口。教学 latch+AND 不是已映射工艺 ICG，任意时刻改变控制可能产生毛刺。还需对实际扫描 FF 时钟端验证，不能只看端口名。

10 · 为什么负沿段常排在正沿段前面？是否绝对？

在特定同相扫描波形与宏周期定义下，这种顺序能让跨边沿接收端获取所需旧值，减少同周期过度推进风险。结论取决于脉冲次序、SI/SO窗口和相位，不是所有设计不加条件的铁律。必须画出本项目 N→P 边界的两次活动边沿来回答。

11 · Lock-up 的透明相位如何选？

目的是让源活动边沿后的新值在目的保持窗口内暂时不能通过。正沿源的常见方案是源时钟低电平透明，源上升沿关闭并保留旧值，下降沿后放新值。不同源边沿应重新推导；选择相反电平可能在最需要阻挡时恰好透明。

12 · 降低 scan clock 频率为什么可能修不了 hold？

同边沿 hold 比较最早数据到达与同次目的采样边沿，基本公式不含下一周期长度。若 skew、Tcq,min 和最短路径不变，仅拉长周期并不增加该保持裕量；setup 因下一边沿更晚可能改善。具体波形改变仍应重新分析。

13 · 正 clock skew 对 setup 和 hold 的影响为何相反？

以 Δ=目的−源定义，同频同沿模型里目的更晚为最长数据留更多 setup 时间，却要求旧值保持更久，因此减少 hold slack。回答必须带符号定义，不能只说“正偏斜好/坏”。

14 · Memory bypass、写门控与 observation point 分别解决什么？

写门控防止测试期间误写；bypass 提供已知可控输入以绕开宏输出 X；observation point 或扫描响应 FF 让差异被读出。三者功能不同，存在其中一个不代表其他问题已解决。旁路也不覆盖 memory 阵列内部故障。

15 · D 和 D̅ 表示什么？与未知 X 的关系是什么？

D=(正常1,故障0)，D̅=(正常0,故障1)；它们是可识别差异。X 表示信息不足，不能当作“与0不同所以检测成功”。搜索中的未赋值 X 可通过完成化选0/1，仿真中的宏未知则需控制或掩码，语义不同。

16 · 手算 q/SA1 的一个检测向量，并解释冲突回退。

取 a=1,b=0，c 任意：q=~a&c=0，故障q=1；p=a&b=0，所以 reconv 正常0、故障1。若为 p=0 先尝试 a=0，会与激活时选的 a=1 冲突；撤销该分支再选 b=0。其他合法激活路径也可能产生不同向量。

17 · 为什么 r/SA0 不可测，而 r/SA1 可测？

r=d&e，z=d|r。SA0 激活时 d=e=1，d 已使 z=1，差异被屏蔽；d=0 时 r本来0。SA1 取d=0，正常z=0而故障z=1。不可测结论绑定当前观察边界，若直接观察r则结论会变。

18 · 为什么本工程不是完整 PODEM？

实际实现以故障传播路径、门 cube 和逆向 justification 进行简化 D 算法搜索，未实现完整工业 D/J-frontier。PODEM 有特定的 PI 决策、目标选择和 backtrace/implication 结构；不是所有回溯程序都可称 PODEM。按实现如实命名比采用响亮术语更重要。

19 · ATPG 报告未检测，可以直接标 untestable 吗？

不可以。必须区分完整证明、预算中止、不支持模型和 X 阻断。本小锥可穷举32组合验证不可测；一般大电路“没有找到”不等于“不存在”。未解决故障仍须留在原始分母中。

20 · 22 个故障的 coverage 为什么不代表整颗 DUT？

它只枚举 fault_cone 的11条stem线各SA0/SA1，没有枚举其他组合锥、每个branch、扫描新硬件、memory阵列或其他故障模型。全DUT回放证明访问与观测路径可工作，但不会把局部故障集合自动扩展成全芯片集合。

21 · 为什么要用穷举 oracle 和 HDL 回放两层检查？

穷举为小锥提供完整输入空间的检测性基准，验证搜索与分类；HDL回放验证实际连接、位序、边沿和状态捕获。二者能发现不同错误，任何一层都不能单独替代另一层。

22 · 多链长度平衡后为什么还要考虑物理重排？

逻辑上相邻的FF可能相距很远，长扫描线增加布线拥塞和数据延迟。物理重排在允许的边沿/时钟分组内改变顺序，必须更新映射和测试向量并重验。链长相等不等于线长短，更不等于所有时序满足。

23 · 如何报告扫描面积开销，才不混淆单位？

先区分通用单元数量与工艺面积。真实面积比较需同一库、映射和面积范围，报告(A_after−A_before)/A_before；NAND2等效门数还需除以相同库参考NAND2面积。未做映射时只给结构数量，不猜测达标。

24 · 对外说“项目已跑通”，最少应给出哪些证据？

固定源版本和工具信息、v0功能基线、实际网表盘点、v0/v1/v2规则范围、扫描映射与Shift/Capture回放、ATPG向量及独立故障仿真、原始分母与未测分类、负例被拦截的结果，以及未完成的物理签核项目。网页只是这些证据的阅读入口。

五项实操答辩

  1. 从连接解释规则：任选 v0 时钟或复位违例，指出原FF、控制来源、v1修复连接与对应验证。验收：不只复述警告文字。
  2. 从一位解释整条链：选择word_q的一位，手写SI发送位置、Capture边沿、目标响应位置与SO比较时刻。验收：与真实mapping/TB一致。
  3. 从失败解释Lock-up：复现无Lock-up反例，用两个边沿说明旧值如何被新值抢先覆盖。验收：给出偏斜与透明相位，而非只说“跨域不安全”。
  4. 从一个故障解释coverage：任选可测故障与r/SA0，分别给向量和不可测证据，指出固定分母。验收：能区分局部cut与全DUT。
  5. 从一次变更解释重验：设想将两条链位置互换，列出必须更新的mapping、patterns与回归。验收：不能只改网表就宣布完成。
